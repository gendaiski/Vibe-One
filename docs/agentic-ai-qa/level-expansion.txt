0|1|Advanced|How do you measure uncertainty without trusting a model's confidence claim?|Use observed performance on representative labeled tasks, calibration experiments when probabilities are available, and evidence checks suited to the decision. 0|2|Basic|What is the difference between input and output tokens?|Input tokens encode the material sent to the model; output tokens are generated in response. Both can affect cost and capacity, with provider-specific accounting for caching or reasoning. Multi-step agents repeat this accounting across calls. Use reported usage instead of estimating the whole task from its final answer length.
0|2|Advanced|How do you prevent caching from returning unauthorized agent results?|Include identity, tenant, permission-relevant scope, input version, and freshness requirements in cache design. Revalidate access before returning sensitive content and invalidate on relevant policy changes. Avoid caching side-effect execution as if it were a pure read. Test cross-user and revoked-access cases explicitly.
1|0|Intermediate|How do you write examples that do not overfit one request?|Vary wording, input structure, and edge conditions while preserving the intended rule. Use the smallest set that improves measured task behavior.
1|0|Advanced|How do you evaluate prompt robustness across changing context?|Test the same task under irrelevant material, reordered evidence, conflicting untrusted instructions, and different context lengths. 1|1|Basic|What is a structured handoff between prompt stages?|It is a defined output from one stage that becomes validated input for the next, such as extracted fields with source references. Use a schema and explicit missing-value handling. The next stage should not need to guess what an informal paragraph means. Preserve uncertainty instead of converting it into a definite fact.
1|1|Advanced|How do you avoid error amplification in prompt chains?|Validate intermediate outputs, keep supporting evidence, and stop or recover when an upstream stage lacks required information. Evaluate each stage and the complete task because locally plausible outputs can combine into a wrong result. Avoid repeated paraphrasing that loses qualifiers. Add stages only when they improve end-to-end outcomes.
1|2|Basic|What belongs in a prompt release record?|Record the instruction text, examples, schema, model configuration, tool versions, release identifier, and evaluation results. Link the change to its intended outcome. This allows later failures to be reproduced and compared. A screenshot of the final prompt is less useful than a versioned source file.
1|2|Advanced|How do you roll back a prompt change safely?|Restore a known configuration while accounting for in-flight runs and state-format compatibility. Determine whether external actions already occurred and reconcile affected tasks. Monitor whether the rollback fixes the targeted regression. Reverting text alone may not restore behavior if tools, models, or source data changed at the same time.
2|0|Intermediate|What validation should happen before dispatching a tool call?|Check the tool is available to the caller, parse the arguments, validate schema and business constraints, and authorize the exact resource and operation. Enforce deadlines and budgets. For writes, establish idempotency or outcome-checking behavior. Only then execute and return the actual result to the model.
2|0|Advanced|How do you handle a model response containing several tool calls?|Determine whether calls are independent or have ordering and shared-state dependencies. Validate and authorize each one separately. Parallelize only when semantics allow it, correlate every result, and handle partial success explicitly. A model emitting multiple calls does not guarantee they are safe to execute concurrently.
2|1|Basic|What is a tool schema?|A tool schema describes the arguments and types a caller may supply, often with descriptions and required fields. It helps the model construct a request and lets code reject malformed inputs. It does not prove permission, business validity, or that execution succeeded. Those checks belong in the application and service.
2|1|Advanced|How do you design a high-level tool without hiding consequential actions?|Define its exact side effects, input constraints, review requirements, and result states. Separate planning or preview from committing changes where needed. Make partial completion observable and expose stable operation identifiers. Evaluate whether reduced call complexity preserves the user's ability to understand and control the resulting action.
2|2|Basic|What should an agent do if a required tool is unavailable?|Explain the missing capability and which part of the task is blocked. Continue useful work that does not depend on it, such as preparing an artifact or inspecting available evidence. Do not fabricate execution or silently use a different account. Offer a concrete next step consistent with the task.
2|2|Advanced|How do you prevent retries from multiplying side effects?|Use a stable operation identity, enforce idempotency at the write service, and reconcile unknown outcomes before issuing a new operation. Bound retries and distinguish transient failures from invalid requests. Test crashes between external completion and local recording. Retry logic should follow operation semantics, not a universal retry-on-error rule.

Keep autonomy where its benefits exceed the added uncertainty and operational burden.
3|1|Advanced|How should an agent runtime enforce resource budgets?|Track step, time, token, tool, and monetary limits in authoritative runtime state. 6|0|Advanced|How do you evaluate a retrieval system for changing enterprise data?|Use queries with known relevant evidence, document versions, and access scopes, including recent edits and revoked permissions. 6|1|Basic|Does storing a conversation mean the model remembers it?|No. Storage preserves data outside the active request, while recall requires selecting and supplying relevant information to the model. 6|1|Advanced|How do you choose between a larger context window and selective retrieval?|Compare task accuracy, evidence coverage, cost, latency, and permission handling under realistic document volumes. 7|0|Advanced|How do you estimate agent reliability from repeated trials?|Define success and run representative cases repeatedly under controlled conditions. 7|1|Basic|What is an evaluation rubric?|A rubric states the criteria and evidence used to grade a result, such as factual support, task completion, and permission adherence.
